# Demo Seed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a safe, deterministic and idempotent command that populates a realistic DevSquad PostgreSQL database without changing the production schema or running automatically at application startup.

**Architecture:** Keep demo data outside Flyway migrations. A single transactional SQL script owns the dataset and uses a marker activity event to make reruns no-ops; a small shell wrapper supplies local `psql`/Docker execution and documents the explicit production command. The script discovers the existing `devsquad` hub and active master, preserving Clerk-managed identity while adding synthetic accounts and complete domain relationships.

**Tech Stack:** PostgreSQL 18 SQL/PLpgSQL, `psql`, Bash, Quarkus/Flyway schema, Gradle verification.

## Global Constraints

- Never add demo rows to a Flyway migration or execute the seed during normal Quarkus startup.
- The seed must run in one transaction and roll back entirely on any constraint or SQL error.
- A fixed marker (`DEMO_SEED_V1`) must make a second execution a no-op.
- Existing hubs, accounts, memberships and application data must be preserved; only the seed namespace may be inserted or updated.
- Synthetic Clerk IDs must be clearly prefixed (`seed-user-`) and must not contain secrets or real user data.
- Seed values must satisfy every check, foreign-key, partial-unique and array/JSON constraint in `V1__initial_schema.sql`.
- The wrapper must support local Compose and an explicit `PSQL_URL`/`PG*` connection; it must not silently target production.

### Task 1: Define the executable seed contract and failing verification

**Files:**
- Create: `scripts/seed-demo.sh`
- Create: `scripts/seed-demo.sql`
- Create: `src/test/java/com/devsquad/seed/DemoSeedContractTest.java`

**Interfaces:**
- `scripts/seed-demo.sh` accepts `SEED_PSQL_URL` or standard `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`; with no connection variables it executes `docker compose exec -T postgres psql`.
- `scripts/seed-demo.sql` is executed through `psql -v ON_ERROR_STOP=1 -f` and emits `demo_seed_v1: inserted` or `demo_seed_v1: already_present`.
- The contract test requires the script and wrapper to exist, the marker name to be present, and the wrapper to pass `ON_ERROR_STOP=1`; it deliberately fails before the files are implemented.

### Task 2: Implement the transactional dataset

**Files:**
- Modify: `scripts/seed-demo.sql`

**Interfaces:**
- The script resolves the default hub by slug `devsquad`, creates it only when absent, resolves an existing active master, and creates a deterministic `seed-master` fallback only for an empty local database.
- It inserts 23 synthetic accounts, a second `opensource-lab` hub, hub roles, six projects, five proposal states, project memberships, recruitment rounds/positions/forms/questions/applications, invitations, workflow columns, milestones, labels, 72 tasks, assignees, labels, comments, pending attachments, activity and notifications.
- All generated child UUIDs are created inside the transaction; the fixed marker activity event is inserted last.
